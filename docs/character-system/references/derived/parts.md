# Source-to-runtime part map

All sources: `../../reference_manifest.json` and `../flat-crops.json`.

| Semantic part | Source | Parent / fit | Change class |
| --- | --- | --- | --- |
| `head_base` | Blank skull, ears removed | Head origin; face controls | Editable static path |
| `ear_L`, `ear_R` | Separate original ear pair | Skull attachment; uniform size | Independent source selection |
| `hair_back` | Completed scalp/interior plus original hair | Scalp/lock skin weights | Static inferred overlap |
| `hair_front` | Source bangs/side locks, repaired ear notches | Same weights; hand-off below chin | Fitted static paths |
| `eye_L`, `eye_R` | Selected feature recipe | Scaled to current skull width; mirrored | Compatible cubic parameters |
| `brow_L`, `brow_R` | Row's separate brows | Current eye frame | Fitted cubic / stroke |
| `nose`, `mouth` | Blank face marks | Face centre line | Static short strokes |
| `outfit_set` | Whole clothed figure | Chin/neck attachment; fixed source geometry | Atomic asset swap |
| `portrait_background` | Existing map sampler | Profile frame | Independent background |

Outfit source rows (zero-based): 0, 2, 3, 4, 5, 7, 8, 10, 13, 14, 15, 16, 17,
18. Rows with long hair crossing the outfit were excluded to avoid retaining the
old hairstyle under a replacement head. Shoes, limbs, clothing, visible hands,
and any costume detail in these sets remain together. No joint rotation or
garment decomposition is performed in the static profile.

Wig skin weights follow only upper-cranium width and temple attachment.
Fifteen guides sample the field. The map keeps y unchanged and blends cap width
into rigid lateral translation for lower locks. Eight scalp-width samples per
side prevent a wide upper cranium from protruding above a narrow cap. Ear tips,
cheeks, jaw and chin do not enter the hair field. Complete curves are adaptively
resampled; the rest shape retains the original source proportions.

The reference neutral head, narrow/wide fit extremes, 19 source head identities,
14 outfit swaps and 64/128-pixel previews are generated by
`tools/render_character_library.cpp`. These reviews render production code,
rather than a separate reconstruction used only in documentation.
